# EPP code: the domain transfer code explained

<p class="post-meta">By <a href="https://halit.org">Halit Sever</a> · <time datetime="2026-11-28">28 November 2026</time></p>

<p class="lead">To move a domain to another registrar, the new registrar asks for an EPP code. It goes by many names (auth code, authorization code, transfer key, AuthInfo) and it is the one piece of the transfer that proves the request comes from the domain's holder. Here is where it comes from, how to get it, and what ICANN requires of your registrar.</p>

## What the code is

Registries and registrars speak EPP, the Extensible Provisioning Protocol. In EPP's domain mapping, [RFC 5731](https://www.rfc-editor.org/rfc/rfc5731), every domain object has an `authInfo` element: authorization information the registry checks before it lets another registrar take the domain. The code is set by the current registrar (the registrar of record) and stored at the registry. When the gaining registrar sends the `transfer` command, it includes the code, and the registry only accepts the request if the code matches.

ICANN's [Transfer Policy](https://www.icann.org/resources/pages/transfer-policy-2016-06-01-en) adds rules for gTLDs such as .com, .net and .org:

- Codes generated by a registrar must be unique per domain.
- The code identifies the domain holder. It does not replace the separate authorization step the policy requires, usually a confirmation email.
- A registrar that does not let you generate the code yourself must give it to you, and remove the transfer lock, within five calendar days of your request.
- It must not make getting the code harder than changing your contact or nameserver details.
- It must not refuse to release the code, or lift the lock, only because of a payment dispute with you.

ccTLDs set their own rules. Some use a code under another name, some move domains differently. Check the country registry's transfer page.

## How to get it

1. **Sign in at your current registrar** and open the domain's settings. The code is usually under "Transfer", "Auth code" or "EPP code". Many registrars email it rather than show it.
2. **Unlock the domain** in the same place. The lock is the status `clientTransferProhibited` (`client transfer prohibited` in RDAP), and the registry refuses transfers while it is set. [Domain status codes](/blog/domain-status-codes) lists the other locks.
3. **Check the status.** Run `curl -sL https://rdap.org/domain/example.com | jq -r '.status[]'`, or use the [domain expiry checker](/domain-expiry-checker/). The transfer lock should be gone. If a `server transfer prohibited` remains, the registry set it and your registrar has to ask for its removal.
4. **Give the code to the new registrar** when you start the transfer, and approve the confirmation email if one arrives.

If the registrar does not answer, ICANN's five-day rule applies to gTLDs, and ICANN accepts complaints about registrars that ignore it.

## Why a transfer can still be refused

A correct code is not the only check. The Transfer Policy lets or requires the losing registrar to deny a transfer in listed cases, including evidence of fraud, an unpaid previous registration period, a pending dispute proceeding (UDRP, URS or TDRP), a court order, an express objection by the holder, and the 60-day windows after a registration, a previous transfer or a change of registrant, unless the holder opted out of the last one. Expiry on its own is not a reason. [Can you transfer a domain after it expires?](/blog/transfer-expired-domain) goes through each case, including domains in redemption.

## Keep the code private

Anyone with the code and an unlocked domain can start a transfer. Treat it like a password:

- Request it only when you are ready to move, and keep the domain locked until then.
- Enter it only at the registrar you chose to move to. Do not send it to anyone who emails or calls about your domain. [Domain expiry scam emails](/blog/domain-expiry-scam-email) shows the pattern of these messages.
- If you think the code leaked, ask your registrar for a new one; registrars can change the stored `authInfo` value.

## After the transfer

A completed gTLD transfer usually adds one year to the registration. Look the domain up again to confirm the new expiry date and registrar. If you monitor it in [Supadomain](/), press **Refresh** on the domain so it reads the new expiry date from RDAP; Supadomain does not repeat lookups on its own.

## FAQ

### What is an EPP code?

It is the password-like code a registry stores for each domain. The new registrar sends it with the transfer request to show that the domain holder agreed. It is also called an auth code, transfer code or AuthInfo code.

### How long does a registrar have to give me the EPP code?

Under ICANN's Transfer Policy for gTLDs, a registrar that offers no self-service tool must give you the AuthInfo code and remove the transfer lock within five calendar days of your request.

### Can a registrar refuse to give me the EPP code?

Not because of a payment dispute alone, under ICANN's Transfer Policy. It can deny a transfer for the reasons the policy lists, such as a court order, a dispute proceeding or the 60-day locks.
